पाठ १ (Lesson 1)

The Sanskrit Sentence (वाक्य) & First Verbs

In Sassembly, every instruction is structured as a complete Sanskrit sentence (वाक्य). Unlike Western assembly languages that rely on rigid syntax like ADD R1, R2, R3 or bracketed memory operands [R1 + 0x8], Sassembly follows natural Sanskrit grammar:

  • Verb First: The first token in a statement is always the Kriyāpada (verb/mnemonic).
  • Terminator Mark: Every instruction ends with a Pāṇinian daṇḍa (।).
  • Comments: Comments start with a circle mark (॰) to end of line.

॰ Lesson 1: Our first Sassembly sentence
योगः कम् खन गन ।    ॰ Mnemonic is योगः (ADD). Writes sum of ख and ग into क.

पाठ २ (Lesson 2)

The 5 Kāraka Sigils (पञ्च-कारकाणि)

Operand roles in Sassembly are marked by kāraka sigils (derived from Sanskrit noun declensions / Vibhakti) rather than positional ordering:

म्
कर्म (Karma)
Destination (Write here)
न
करण (Karana)
Source (Read from here)
त्
अपादान (Apadana)
Load Address (Load from [addr])
य्
सम्प्रदान (Sampradana)
Store Address (Store to [addr])
ए
अधिकरण (Adhikarana)
Locus (In / At environment)

Free Operand Ordering: Because the role is bound to the token via its kāraka sigil, योगः कम् खन गन । and योगः खन गन कम् । produce the exact same deterministic binary instruction!

पाठ ३ (Lesson 3)

The 32 RV64 Registers (३२ कोष्ठकाणि)

All 32 general-purpose 64-bit integer registers have authentic Sanskrit names mapped directly to the standard RISC-V ABI:

  • शून्यः (zero / x0) — Hardwired zero
  • पुनःस्थानम् (ra / x1) — Return address for functions
  • स्तूपसूचकः (sp / x2) — Stack pointer
  • विश्वसूचकः (gp / x3) • तन्तुसूचकः (tp / x4) — Global & Thread pointers
  • क्षणिक०..क्षणिक६ (t0–t6) — 7 Temporary registers
  • अर्थ०..अर्थ७ (a0–a7) — 8 Function argument / return value registers
  • स्थिर०..स्थिर११ (s0–s11) — 12 Callee-saved preserved registers
पाठ ४ (Lesson 4)

Sanskrit Numerals (सङ्ख्याः)

Sassembly provides explicit radix prefixes with Devanagari numerals:

  • Hexadecimal (०षोड्): ०षोड्१०००० (0x10000). Hex digits 10–15 are represented by Sanskrit vowels: अ (10), आ (11), इ (12), ई (13), उ (14), ऊ (15). Example: ०षोड्५५५.
  • Binary (०द्वि): ०द्वि१०११० (0b10110).
  • Octal (०अष्ट): ०अष्ट७७ (0o77).
  • Decimal: १२३ (123).
पाठ ५ (Lesson 5)

Directives & Sections (निर्देशाः)

Directives give instructions to the assembler (साधनम्) and are wrapped in double daṇḍas (॥ ... ॥): 

॥ कोष्ठकम् ॱपाठ ॥            ॰ Switch to code section (.text)
॥ कोष्ठकम् ॱदत्त ॥            ॰ Switch to data section (.data)
॥ अष्टकाः उक्तम् नमस्ते इति ॥ ॰ Emit UTF-8 string bytes
॥ स्थानम् ८ ॥                 ॰ Allocate 8 zero bytes
॥ संरेखः ४ ॥                  ॰ 4-byte address alignment

Arithmetic, Logic & Bitwise Shifts

Sassembly provides 49 mnemonic families covering all RV64GC operations:

  • वियोगः (SUB) • गुणनम् (MUL) • भागः (DIV) • शेषः (REM)
  • युक्तम् (AND) • विकल्पः (OR) • वैषम्यम् (XOR) • व्यत्ययः (NOT)
  • वामसरणम् (SLL - Shift Left) • दक्षिणसरणम् (SRL - Shift Right Logical) • सचिह्नदक्षिणसरणम् (SRA - Shift Right Arithmetic)
पाठ ७ (Lesson 7)

Memory Hierarchy & Sizing Extents (व्याप्ति)

Sizing suffixes (Vyāpti) determine the bit width of instructions:

  • ॱअ८ — 8-bit Byte
  • ॱअ१६ — 16-bit Halfword
  • ॱअ३२ — 32-bit Word
  • ॱअ६४ — 64-bit Quadword (Default if omitted)
आहारःॱअ८ क्षणिक०म् क्षणिक१त् ०न ।  ॰ Load 8-bit byte from [t1 + 0] into t0
निधानम्ॱअ३२ क्षणिक१य् ०न क्षणिक०न । ॰ Store 32-bit word from t0 to [t1 + 0]
पाठ ८ (Lesson 8)

Control Flow, Branches & Loops (नियन्त्रण-प्रवाहः)

Conditional branches compare two values and jump to a label (marked by नामपदम्ॱॱ):

  • समलङ्घनम् (BEQ - Branch if Equal)
  • विषमलङ्घनम् (BNE - Branch if Not Equal)
  • न्यूनलङ्घनम् (BLT - Branch if Less Than)
  • अन्यूनलङ्घनम् (BGE - Branch if Greater or Equal)
  • लङ्घनम् (JAL - Jump and Link)
पाठ ९ (Lesson 9)

Akṣara Normalisation & Orthographic Closure

In Sassembly, the atom of text is the Akṣara cluster, not individual byte code points. क्ष is treated as a single cluster. This eliminates homoglyph attacks and bidirectional unicode overrides structurally at the compiler level. Zero foreign ASCII characters may appear in Sassembly source.

पाठ १० (Lesson 10)

Calling Conventions & Stack Frame Management

Function arguments are passed in अर्थ०..अर्थ७. Before calling a nested function, the caller must preserve the return address (पुनःस्थानम्) on the stack using स्तूपसूचकः (sp): 

॰ Prologue: Allocate 16 bytes on stack
वियोगः स्तूपसूचकःम् स्तूपसूचकःन १६न ।
निधानम्ॱअ६४ स्तूपसूचकःय् ८न पुनःस्थानम्न ।

॰ Call Subroutine
लङ्घनम् पुनःस्थानम्म् उपकार्यम्य् ।

॰ Epilogue: Restore Return Address and deallocate stack
आहारःॱअ६४ पुनःस्थानम्म् स्तूपसूचकःत् ८न ।
योगः स्तूपसूचकःम् स्तूपसूचकःन १६न ।
सापेक्षलङ्घनम् शून्यःम् पुनःस्थानम्त् ०न । ॰ RET

पाठ ११ (Lesson 11)

Boot Proofs vs Isolated U-Mode Applications

SanOS enforces a strict architectural boundary between two program classes:

धातु-प्रमाणम् (Boot Proofs)

Bare-metal machine/supervisor mode. Boots at 0x80000000. Directly owns the UART memory-mapped device at 0x10000000.

अतिथि-अनुप्रयोगः (Guest Apps)

U-mode isolated. Placed at 0x20000000. Cannot access hardware devices; communicates via आज्ञापनम् (ecall) to a granted supervisor surface.

पाठ १२ (Lesson 12)

Atomic Operations & Multiprocessing (परमाणवः)

Native atomic primitives in Sassembly guarantee lock-free synchronization across CPU cores:

  • परमाणुपठनम् (LR - Load Reserved)
  • परमाणुलेखनम् (SC - Store Conditional)
  • परमाणुविनिमयः (AMOSWAP - Atomic Swap)
  • परमाणुयोगः (AMOADD - Atomic Add)
पाठ १३ (Lesson 13)

64-bit Floating Point Architecture (भिन्न-सङ्ख्याः)

Floating point operations utilize 32 dedicated registers (भिन्न०..भिन्न३१):

  • भिन्नाहारः (FLW/FLD) • भिन्ननिधानम् (FSW/FSD)
  • भिन्नयोगः (FADD) • भिन्नगुणनम् (FMUL) • वर्गमूलम् (FSQRT)
पाठ १४ (Lesson 14)

The 3 Core System Elements (त्रि-व्यवस्था-तत्त्वानि)

All higher-level applications in SanOS are constructed from 3 core elements:

  1. E1 · द्वारपालः (Dvarapala): Smart PTY and Sanskrit Devnagari terminal subsystem.
  2. E2 · चित्रम् (Chitra): Hardware-portable 2D/3D graphics rasterizer and compositor (Mandapa).
  3. E3 · जालम् (Jala): Sanskrit TCP/IP, UDP, and network driver stack.
पाठ १५ (Lesson 15)

SanOS Native Applications (मूल-अनुप्रयोगाः)

The 4 fundamental native applications built on the 3 core elements:

  • N1 · साधनम् (Sadhana): Sassembly compiler, linker (Kosha), and builder toolchain.
  • N2 · भाण्डारम् (Bhandara): Sanskrit visual filesystem browser & explorer.
  • N3 · गवाक्षः (Gavaksha): Web browser rendering classical HTML/JS and Sassembly-web (Vastu).
  • N4 · नादः & रूपम् (Nada/Rupa): Multimedia A/V playback engine and codec suite.

Zero-Mass Computing & Verification

The fundamental philosophy of Sanskrit computing is unloading the bloat:

  • 64 KiB Kernel (vs 100 MB Linux)
  • 4 KiB Hello World Binary (vs 300 KB Rust)
  • ≤ 2x Build Mass Ratio (vs 1000x Cargo)
  • Zero 3rd-Party Runtime Dependencies in core execution path.
